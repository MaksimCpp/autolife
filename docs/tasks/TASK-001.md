### TASK-001.02 — PostgreSQL и миграции

- [x] Статус: done.
- Зависимости: TASK-001.01.
- Реализация: Создать pgx pool, runner golang-migrate, отдельные роли подключения и процедуру официальных River migrations; добавить тест подключения. Использовать PostgreSQL 17 и проверить совместимость pgx/River InsertTx с точными версиями и официальными миграциями.
- Критерии приёмки: Чистая БД мигрируется повторяемо; readiness отражает недоступность БД. Commit делает job видимым, rollback не оставляет job. Обе процедуры миграций проверены на пустой и существующей базе.
- Проверка (2026-11-25): `gofmt -l backend infrastructure/smoke/river` не нашёл отклонений. В `backend` прошли `go mod verify`, `go vet -mod=readonly ./...`, `go test -race -mod=readonly ./...` и `go build -mod=readonly ./cmd/...`. `docker compose --env-file <временный .env> config --quiet` прошёл с локальными параметрами, созданными штатным скриптом.
- Интеграция: на временном PostgreSQL 17.9 дважды прошли миграции приложения и официальные миграции River 0.51.2 через `rivermigrate` с pgx 5.11.0. Readiness вернул 503 до миграций, 200 после, 503 при остановке БД и 200 после восстановления. `go test -mod=mod -count=1 -v -run '^TestOfficialMigrations$' ./...` во временном стенде подтвердил, что worker видит job после commit и не видит её после rollback. Тест использовал штатные роли и выполнил `migrate grant-river-access` после каждого прогона River.
- Штатный River CLI 0.51.2 с переменными `PG*` применил миграции 001–008 на пустой схеме очереди, при повторе сообщил `no migrations to apply`. Проверен и контейнерный путь: `docker compose up --build --wait api worker`, повторный `docker compose run --rm --no-deps migrate` и `docker compose run --rm --no-deps river-smoke` прошли. Тесты commit и rollback прошли под штатными ролями.
