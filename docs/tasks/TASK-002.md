AGENTS.md; docs/ROADMAP.md; docs/REQUIREMENTS.md; docs/TESTING.md. Дополнительно (пути относительно docs/): REQUIREMENTS.md, DATABASE.md, API.md, SECURITY.md, UI_UX.md.

## Подзадачи и критерии приёмки

### TASK-002.01 — Схема аккаунтов

- [x] Статус: done.
- Зависимости: зависимости этапа, указанные выше.
- Реализация: Написать миграции users/user_settings/sessions/auth_tokens, ограничения уникальности email и сроки токенов; pgx repositories. Уточнить DDL ограничений owner, privacy jobs и P0 audit. Создать общую Transactional Outbox и ограничения event ID/logical key до producers.
- Критерии приёмки: Конкурентная регистрация не создаёт дубли; интеграционные тесты миграций проходят. DDL отвергает недопустимые связи и состояния. Событие и доменное изменение коммитятся или откатываются вместе.
- Проверка: На PostgreSQL 17 прошли первое и повторное применение миграций. TestAccountMigration в режиме race подтвердил единственную запись при конкурентной регистрации, ограничения DDL и атомарность outbox.

### TASK-002.02 — Регистрация и подтверждение

- [x] Статус: done.
- Зависимости: TASK-002.01.
- Реализация: Реализовать POST /auth/register и /auth/verify, Argon2id с измеренными параметрами, одноразовые hashed tokens, отправку через тестовый mail adapter. Применить pre-auth CSRF/Origin, записать user.registered в outbox при commit.
- Критерии приёмки: Просроченный/повторный token отклоняется; ответ регистрации не раскрывает наличие аккаунта. Неверные Origin/CSRF и повтор использованного токена отклоняются.
- Проверка: TestRegistrationAndVerification в режиме race проверил generic 202, отклонение Origin/CSRF, истечение и повтор токена. BenchmarkPassword на Apple M4 показал 16,0 мс/операцию и 19,9 МБ выделений; m=19456, t=2, p=1. Доставка через Mailpit дополнительно проверяется в E2E.

### TASK-002.03 — Сессии

- [x] Статус: done.
- Зависимости: TASK-002.02.
- Реализация: Реализовать login/logout, middleware owner, opaque random token с hash в БД, TTL, revoke, cookie flags, CSRF/Origin и rate limit. Реализовать GET /auth/csrf, outbox login_succeeded и параметры SECURITY.
- Критерии приёмки: Неверный пароль, истечение, отзыв, CSRF и чужие ресурсы проверены; секреты не логируются. Токены разделены по pre-auth/session и не сохраняются в логах.
- Проверка: интеграционный race-тест проверил неверный пароль, истечение и отзыв сессии, разделение pre-auth/session CSRF и ответ 429 после лимита. Проверка чужих ID расширяется в TASK-002.05.

### TASK-002.04 — Восстановление доступа

- [x] Статус: done.
- Зависимости: TASK-002.03.
- Реализация: Реализовать forgot/reset, изменение пароля с повторной авторизацией и отзывом необходимых сессий. Описать OpenAPI смены пароля и политику verify/reset. Писать события аудита.
- Критерии приёмки: Повторный reset невозможен; ответы не раскрывают аккаунты; старые сессии отозваны по политике. Reset отзывает все сессии, смена пароля ротирует текущую и отзывает остальные.
- Проверка: PostgreSQL race-тест проверил одинаковый 202 forgot, отклонение replay, отзыв всех сессий при reset и ротацию при смене пароля.

### TASK-002.05 — Профиль

- [x] Статус: done.
- Зависимости: TASK-002.04.
- Реализация: Реализовать GET/PATCH /me, валидацию locale/timezone/theme/consent, управление своими сессиями; не принимать owner из клиента. Добавить GET/DELETE сессий по маршрутам API и настройку opt-in.
- Критерии приёмки: Профиль сохраняется; недопустимые значения отвергаются; чужие сессии недоступны. Пользователь отзывает только свою сессию, необязательный сбор по умолчанию выключен.
- Проверка: PostgreSQL race-тест двух владельцев проверил сохранение настроек, opt-in по умолчанию, валидацию, отклонение owner из запроса и изоляцию списка и отзыва сессий.

### TASK-002.06 — Экспорт и удаление

- [x] Статус: done.
- Зависимости: TASK-002.05.
- Реализация: Реализовать защищённые запросы /me/export и DELETE /me с недавней авторизацией, durable запись запроса, статус и отзыв сессий; расширять обработку данных вместе с будущими модулями. Реализовать durable состояния, маршруты статуса и выдачи экспорта, последние credentials, идемпотентность и запрет новой работы при deleting. В 002 проверяются аккаунт и сессии. Файлы подключаются в 003, workflow в 004, запуски в 005, шаблонные ссылки в 008, уведомления и аналитика в 009.
- Критерии приёмки: Экспорт текущих данных не содержит секретов; удаление блокирует новые действия, проверена очистка текущих сущностей. Очередь общего engine подключается в 005. Проверить повтор запроса, приватность/TTL экспорта, блокировку новых операций и аудит. Полный сценарий и replay удалений проверяются в 010.
- Проверка: PostgreSQL race-тест проверил повтор запроса, изоляцию статуса и скачивания, экспорт без секретов, TTL, отзыв сессий, блокировку при недоступном restore journal, повтор подтверждения, очистку и аудит.
