## Фактические проверки

- Сборка linux/arm64 с libvips 8.17.3-r1 прошла. [SBOM](../sbom/image-transform-linux-arm64.cdx.json) содержит 85 runtime APK. Нативная smoke-матрица прошла все девять пар JPEG/PNG/WebP, сохранение alpha, фон JPEG, EXIF-ориентацию и очистку GPS/EXIF, совместимый ICC → sRGB, округление, режимы resize, качество и lossless, отказ для повреждённых/слишком больших файлов и SVG.
- На PostgreSQL 17.9, River 0.51.2 и отдельном SeaweedFS 4.55 `TestImageWorkflows` выполнил цепочку convert → resize → compress на трёх картинках. Конвертация использовала тот же нативный образ через тестовый адаптер. Проверены порядок, реальные JPEG в S3, три логических события, пакет из 50 разных исходников, отказ на втором элементе, staging, повтор и единственное событие при двух попытках, отмена, таймаут и освобождение резерва. Пакет 50 и сценарии сбоев использовали тестовый преобразователь.
- Прошли миграции 000011 up/repeat и down/up на пустых таблицах, регрессии execution и fileflow под race detector, `go test -race -mod=readonly -count=1 ./...`, `go vet -mod=readonly ./...`, `go build -mod=readonly ./cmd/...`, `go mod verify`, Docker Compose config, YAML OpenAPI, `git diff --check` и Gitleaks без находок. Последовательный прогон интеграционных пакетов на общей тестовой очереди прошёл с `-p 1`.
- Unit-тесты launcher подтверждают проверку профиля, порядок отмены и запрет повторной работы по подтверждённому attempt ID после перезапуска. Целевой AppArmor/cgroup v2 и сквозное исполнение через операторский Unix launcher остаются открытыми блокирующими полевыми критериями TASK-010.02/.09. HEIC/HEIF и SVG остаются в TASK-007A.
