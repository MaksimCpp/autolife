# TASK-006 — Действия изображений

Статус: planned. Зависимости: 005.

## Цель

Реализовать реальные действия обработки изображений в sandbox.

## Источники требований

AGENTS.md; docs/ROADMAP.md; docs/REQUIREMENTS.md; docs/TESTING.md. Дополнительно (пути относительно docs/): modules/FILE_FLOW.md, modules/WORKFLOW_ENGINE.md, SECURITY.md.

## Подзадачи и критерии приёмки

### TASK-006.01 — Инструмент обработки

- [ ] Статус: planned.
- Зависимости: зависимости этапа, указанные выше.
- Реализация: Подключить утверждённую сборку libvips, зарегистрировать capabilities JPEG/PNG/WebP и написать безопасный adapter. HEIC/HEIF и SVG подключаются в TASK-007A. Закрепить версии, декодеры, SBOM и лицензии выбранного образа.
- Критерии приёмки: Fixtures каждого заявленного формата реально декодируются; неподдерживаемый формат явно отклоняется. JPEG/PNG/WebP подтверждены fixtures именно поставляемого образа.

### TASK-006.02 — Конвертация

- [ ] Статус: planned.
- Зависимости: TASK-006.01.
- Реализация: Реализовать file.image.convert v1, config format/quality/background, нормализацию EXIF orientation и удаление приватных metadata; хранить новый artifact.
- Критерии приёмки: Проверены формат, прозрачность/фон JPEG, ориентация, отсутствие GPS и неизменность исходника.

### TASK-006.03 — Сжатие

- [ ] Статус: planned.
- Зависимости: TASK-006.02.
- Реализация: Реализовать file.image.compress v1 с настройками lossy/lossless по формату и измерением размеров.
- Критерии приёмки: Выход декодируется; UI/результат не обещает уменьшение при большем output; quality вне диапазона отклоняется.

### TASK-006.04 — Изменение размера

- [ ] Статус: planned.
- Зависимости: TASK-006.03.
- Реализация: Реализовать file.image.resize v1 с max_width/max_height, aspect ratio, upscale=false, округлением и лимитом пикселей.
- Критерии приёмки: Fixtures landscape/portrait/small/alpha дают правильные размеры; недопустимые размеры отклонены.

### TASK-006.05 — Пакетная обработка

- [ ] Статус: planned.
- Зависимости: TASK-006.04.
- Реализация: Реализовать обработку списка с сохранением порядка, bounded concurrency, лимит output, атомарную публикацию итоговых refs и очистку частичного результата.
- Критерии приёмки: 50 или согласованный лимит файлов обрабатываются; ошибка одного файла не выдаёт весь batch за успех; отмена очищает workspace.

### TASK-006.06 — Регистрация и статистика

- [ ] Статус: planned.
- Зависимости: TASK-006.05.
- Реализация: Подключить действия к registry, schemas и execution worker, записывать format/count/bytes/duration/outcome; обновить OpenAPI и модульные docs. Соблюдать file.action_completed из словаря.
- Критерии приёмки: Реальный workflow convert→resize→compress проходит E2E на fixtures; тесты cancel/timeout/oversized и повторного запуска проходят. Одна финальная запись на логическое действие, попытки учитываются отдельно.

## Ожидаемый результат

Работоспособные компоненты данного этапа, подключённые к существующему приложению; соответствующие миграции, API/UI/инфраструктура (где предусмотрено), автоматизированные тесты и подтверждённые результаты проверок.

- Прочитать AGENTS.md и перечисленные документы, сверить зависимости и существующий код. При конфликте требований остановиться и зафиксировать вопрос, не менять согласованный контракт самостоятельно.
- Выполнять одну подзадачу за раз в порядке списка; все предыдущие подзадачи этого файла являются зависимостями, если явно не согласован иной порядок. Не переходить к следующей без указания владельца. Отмечать чекбокс только после выполнения критериев; при блокере указать partial/blocked.
- Для задач реализации писать настоящий код, миграции, конфигурации и тесты; подключать компоненты к приложению. Не заменять обязательную функциональность заглушками. Тестовые doubles допустимы только в тестах или явно обозначенном dev режиме.

- Обновить затронутую документацию, список изменённых файлов, ADR при необходимости и статус ROADMAP. Весь этап завершён только после прохождения всех подзадач и итоговых критериев. Остановиться после отчёта.
