# TASK-009 — История и аналитика

Статус: planned. Зависимости: 005,008.

## Цель

Реализовать историю запусков, уведомления и измеримую аналитику.

## Источники требований

AGENTS.md; docs/ROADMAP.md; docs/REQUIREMENTS.md; docs/TESTING.md. Дополнительно (пути относительно docs/): ANALYTICS.md, API.md, DATABASE.md, UI_UX.md.

## Подзадачи и критерии приёмки

### TASK-009.01 — История и детали

- [ ] Статус: planned.
- Зависимости: зависимости этапа, указанные выше.
- Реализация: Подключить страницы history/execution detail к API, фильтры, статусы шагов, attempts, duration, safe errors, output refs и expiry.
- Критерии приёмки: Состояние обновляется после закрытия/возврата страницы; чужие записи недоступны; истёкший artifact корректно показан.

### TASK-009.02 — Управление запусками

- [ ] Статус: planned.
- Зависимости: TASK-009.01.
- Реализация: Добавить кнопки cancel/retry, подтверждения, повторную загрузку отсутствующих входов, отсутствие фиктивного процента прогресса.
- Критерии приёмки: UI различает request cancellation и cancelled; retry создаёт новый execution; ошибки показаны.

### TASK-009.03 — Уведомления

- [ ] Статус: planned.
- Зависимости: TASK-009.02.
- Реализация: Реализовать notifications table, in-app consumer outbox, GET/PATCH notifications, службу email для предусмотренных событий и настройки. Уточнить PATCH /notifications/{id}, retire expired и export/delete.
- Критерии приёмки: Повтор события не создаёт дубль уведомления; сбой email не ломает обработку; пользователь видит только свои записи. Сбой доставки не меняет статус execution. Чужие уведомления недоступны.

### TASK-009.04 — Аналитические события

- [ ] Статус: planned.
- Зависимости: TASK-009.03.
- Реализация: Написать consumer outbox, analytics_events, dedup event_id, allowlist, разделение operational и optional telemetry, consent и retention. Использовать единый версионируемый словарь, согласие/отзыв, denylist содержимого, TTL и пересчёт.
- Критерии приёмки: Повторная доставка не меняет счётчик; отказ от optional analytics соблюдается; приватные поля исключены. Выпуск S3 ссылки не учитывается как подтверждённое скачивание.

### TASK-009.05 — Агрегаты

- [ ] Статус: planned.
- Зависимости: TASK-009.04.
- Реализация: Реализовать analytics_daily и пересчёт late events, уникальные logical runs, success rate по формуле ANALYTICS.md, file bytes и counts, DAU/WAU/MAU/activation/retention. Применять denominators, UTC окна, late events, часы согласия и подавление малых групп по ANALYTICS.
- Критерии приёмки: Фиксированный fixture даёт ожидаемые числа; retries отдельно; границы UTC и нулевой знаменатель проверены. Проверены retries, пустые знаменатели, полностью наблюдаемые когорты и сверка со статусами.

### TASK-009.06 — Пользовательский dashboard

- [ ] Статус: planned.
- Зависимости: TASK-009.05.
- Реализация: Реализовать GET /stats с owner/date filters и Recharts dashboard: runs, success rate, file count/bytes, duration, trend, usage; saved time только с baseline.
- Критерии приёмки: Суммы сверяются с execution records; недоступная метрика не выдумана; обе темы и empty states работают.

### TASK-009.07 — Эксплуатационная статистика

- [ ] Статус: planned.
- Зависимости: TASK-009.06.
- Реализация: Добавить защищённый агрегированный отчёт для владельца (CLI/endpoint по утверждённой модели), метрики Prometheus и базовые Grafana dashboards; без user IDs в labels. Завершить P0 ACL, аудит доступа, экспорт/удаление статистики и уведомлений.
- Критерии приёмки: RBAC проверен; метрики queue/latency/errors доступны только оператору; тесты сверки и privacy проходят. Аудит append-only для обычной роли, ретеншн и безопасный payload проверены.

### TASK-009.08 — Возврат к результату после закрытия вкладки

- [ ] Статус: planned.
- Зависимости: TASK-009.07.
- Реализация: Проверить настоящий сценарий upload → шаблон/цепочка → run → закрыть вкладку → открыть history → скачать.
- Критерии приёмки: Успешный результат, отмена, истечение ссылки и retry с заменой входов видны в реальном интерфейсе.

## Ожидаемый результат

Работоспособные компоненты данного этапа, подключённые к существующему приложению; соответствующие миграции, API/UI/инфраструктура (где предусмотрено), автоматизированные тесты и подтверждённые результаты проверок.
