# TASK-008 — Редактор и шаблоны

Статус: planned. Зависимости: 006,007,007A.

## Цель

Создать полный пользовательский интерфейс MVP на реальном API.

## Источники требований

AGENTS.md; docs/ROADMAP.md; docs/REQUIREMENTS.md; docs/TESTING.md. Дополнительно (пути относительно docs/): UI_UX.md, API.md, modules/FILE_FLOW.md, modules/WORKFLOW_ENGINE.md.

## Подзадачи и критерии приёмки

### TASK-008.01 — Дизайн-система

- [ ] Статус: planned.
- Зависимости: зависимости этапа, указанные выше.
- Реализация: Утвердить референсы и реализовать CSS tokens dark/light/system, синие/голубые/бирюзовые/изумрудные акценты, компоненты shadcn/ui, focus, reduced motion, RU/EN. Проверить значимые границы и focus, WCAG 2.2 AA, reflow 320 CSS px и согласованные токены.
- Критерии приёмки: Обе темы сохраняются; контраст проверен; скриншоты 360/768/1440 без overflow обычных страниц. Проходят ручные keyboard/screen reader проверки и проверка обеих тем.

### TASK-008.02 — Навигация и публичные страницы

- [ ] Статус: planned.
- Зависимости: TASK-008.01.
- Реализация: Написать landing, sidebar/header/mobile nav, overview, privacy/terms links и feature availability; подключить account pages.
- Критерии приёмки: Все доступные маршруты работают; будущие функции не выглядят готовыми; авторизация защищает приватные страницы.

### TASK-008.03 — Файловый интерфейс

- [ ] Статус: planned.
- Зависимости: TASK-008.02.
- Реализация: Реализовать upload/dropzone с прогрессом передачи, list/picker, size/type/TTL, download/delete confirmations и ошибки квот.
- Критерии приёмки: Файлы реально загружаются/скачиваются через API; invalid input и expired artifact видны; доступно с клавиатуры.

### TASK-008.04 — Редактор

- [ ] Статус: planned.
- Зависимости: TASK-008.03.
- Реализация: Реализовать React Flow linear canvas, каталог действий из API, формы config по schema, связи, order, bindings, mobile list и keyboard reorder. Выводить React Flow edges из общего порядка и обеспечить равноправное мобильное представление.
- Критерии приёмки: Пользователь собирает последовательность без JSON; несовместимые связи отклоняются; mobile alternative работает. Добавление, изменение и перестановка доступны одинаково с клавиатуры, мыши и на мобильном.

### TASK-008.05 — Черновики и запуск

- [ ] Статус: planned.
- Зависимости: TASK-008.04.
- Реализация: Подключить save/revision/validate/publish/copy/archive, input file picker, test/manual run, предупреждение unsaved changes и 409 conflict. Тестовый запуск использует expected_revision и immutable snapshot без публикации.
- Критерии приёмки: Редактирование не меняет активный execution; запуск возвращает ID; ошибка поля показана у шага; повторный запуск возможен. Проверить stale revision, сохранение active_version и видимое происхождение теста.

### TASK-008.06 — Каталог шаблонов

- [ ] Статус: planned.
- Зависимости: TASK-008.05.
- Реализация: Написать миграцию/seed templates, GET /templates и instantiate, поиск/категории и мастер параметров; включить шесть шаблонов MVP. Учитывать шаблонные экземпляры в export/delete и template.used.
- Критерии приёмки: Шаблон создаёт независимый workflow; пользователь проходит путь выбора до фактического запуска. Импорт не переносит file refs, secrets и чужой owner.

### TASK-008.07 — Сквозные проверки UI

- [ ] Статус: planned.
- Зависимости: TASK-008.06.
- Реализация: Написать Vitest и Playwright тесты цепочки, шаблона, auth, upload, мобильной навигации, тем и локализации; исправить ошибки accessibility. Ограничить этот E2E доступными экранами до принятия задачи. Закрытие вкладки и поиск результата проверяются в 009.08.
- Критерии приёмки: E2E проходит на реальных API и fixtures, без моков в обязательных потоках; тексты RU/EN полны. Тесты включают два языка, обе темы, мобильный список, snapshot и keyboard.

## Ожидаемый результат

Работоспособные компоненты данного этапа, подключённые к существующему приложению; соответствующие миграции, API/UI/инфраструктура (где предусмотрено), автоматизированные тесты и подтверждённые результаты проверок.

## Правила выполнения и завершения

- Прочитать AGENTS.md и перечисленные документы, сверить зависимости и существующий код. При конфликте требований остановиться и зафиксировать вопрос, не менять согласованный контракт самостоятельно.
- Выполнять одну подзадачу за раз в порядке списка; все предыдущие подзадачи этого файла являются зависимостями, если явно не согласован иной порядок. Не переходить к следующей без указания владельца. Отмечать чекбокс только после выполнения критериев; при блокере указать partial/blocked.
- Для задач реализации писать настоящий код, миграции, конфигурации и тесты; подключать компоненты к приложению. Не заменять обязательную функциональность заглушками. Тестовые doubles допустимы только в тестах или явно обозначенном dev режиме.
- Проверять безопасность, owner scope, ошибки и ограничения там, где применимо. Не использовать реальные production secrets, не выполнять push/deploy без разрешения. Не добавлять функциональность других этапов заранее.
- Запускать применимые проверки из TESTING.md: unit/integration, race для конкурентного Go-кода, frontend lint/typecheck/build и E2E, migration/security checks. Записать фактическую команду, результат и непроверенные условия. Не утверждать, что тест прошёл, если он не запускался.
- Обновить затронутую документацию, список изменённых файлов, ADR при необходимости и статус ROADMAP. Весь этап завершён только после прохождения всех подзадач и итоговых критериев. Остановиться после отчёта.
