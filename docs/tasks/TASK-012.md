# TASK-012 — Integrations и AutoInbox

Статус: planned. Зависимости: 011.

## Цель

Реализовать внешние подключения и обработку входящей информации.

## Источники требований

AGENTS.md; docs/ROADMAP.md; docs/REQUIREMENTS.md; docs/TESTING.md. Дополнительно (пути относительно docs/): modules/INTEGRATIONS.md, modules/AUTO_INBOX.md, SECURITY.md, ANALYTICS.md.

## Подзадачи и критерии приёмки

### TASK-012.01 — Реестр интеграций

- [ ] Статус: planned.
- Зависимости: зависимости этапа, указанные выше.
- Реализация: Написать provider/capability registry, connections/credential_refs migrations, разрешения owner/scope, encrypted storage с rotation.
- Критерии приёмки: Секреты не возвращаются UI; чужие/отозванные connections отклонены перед действием.

### TASK-012.02 — OAuth

- [ ] Статус: planned.
- Зависимости: TASK-012.01.
- Реализация: Реализовать authorization code/PKCE где поддерживается, state одноразовый с TTL, callback, refresh concurrency, disconnect/revoke.
- Критерии приёмки: Mock тесты invalid state, повтор callback, refresh race, scope denial и revoke проходят.

### TASK-012.03 — Telegram

- [ ] Статус: planned.
- Зависимости: TASK-012.02.
- Реализация: Написать bot adapter, безопасную привязку аккаунта, проверку webhook secret/replay, прием добровольно отправленных файлов/сообщений, notifications.
- Критерии приёмки: Чужой chat не привязывается; duplicate update не создаёт дубль; нет доступа к произвольным личным чатам.

### TASK-012.04 — Google сервисы

- [ ] Статус: planned.
- Зависимости: TASK-012.03.
- Реализация: Реализовать Gmail read adapter, Drive upload/download, Sheets append/read и Calendar event create с минимальными scopes; проверить разрешения и verification до включения. Read/capability тестировать отдельно. Включение записи требуется закрыть в 012.05.
- Критерии приёмки: Mock provider contract tests; отсутствие разрешения блокирует функцию; реальный провайдер не объявлен готовым без проверки. Записи недоступны до тестов idempotency, revoke и UNKNOWN_OUTCOME.

### TASK-012.05 — Надёжность внешних записей

- [ ] Статус: planned.
- Зависимости: TASK-012.04.
- Реализация: Реализовать timeout/rate limits/Retry-After, idempotency/reconciliation, UNKNOWN_OUTCOME, явно утверждённую политику разрешённых эффектов. Durable approval подключается после TASK-013.05. Эффекты, требующие интерактивного подтверждения, остаются выключены до 013.05.
- Критерии приёмки: Потеря ответа не вызывает слепую повторную отправку/запись; отзыв доступа останавливает новые операции. Внешний эффект нельзя запустить с непроверенным scope и без согласованной политики.

### TASK-012.06 — Синхронизация входящих

- [ ] Статус: planned.
- Зависимости: TASK-012.05.
- Реализация: Написать sources/cursors/message refs/processing records, initial sync window, checkpoint вместе с durable event, dedup и recovery.
- Критерии приёмки: Повтор письма/потеря cursor не дублируют workflow; архив по умолчанию не обрабатывается.

### TASK-012.07 — Фильтры и вложения

- [ ] Статус: planned.
- Зависимости: TASK-012.06.
- Реализация: Реализовать sender/subject/content/attachment filters, безопасное preview без remote pixels, извлечение вложений через FileFlow, inbox triggers.
- Критерии приёмки: Вредоносный HTML не исполняется; вложение проходит sandbox/квоты; фильтр проверен fixtures.

### TASK-012.08 — Автоматизации входящих

- [ ] Статус: planned.
- Зависимости: TASK-012.07.
- Реализация: Реализовать deterministic tracking extraction, rule-based tasks/receipts где достоверно, digest с пометкой неполных данных, Drive/Sheets/Calendar действия; AI-извлечение подключается в 014. Покрыть известные текстовые форматы и rules-only digest. OCR и AI подключаются в 013 и 014.
- Критерии приёмки: Неизвестные значения остаются пустыми; тестовый чек и письмо проходят цепочку без непредусмотренных внешних эффектов. Текстовый чек известного формата обрабатывается, скан и неизвестные поля дают понятное неполное состояние.

### TASK-012.09 — UI интеграций и Inbox

- [ ] Статус: planned.
- Зависимости: TASK-012.08.
- Реализация: Написать страницы подключения/отзыва, scopes, filters, preview, шаблоны вложений/чеков/сводок, status/error states.
- Критерии приёмки: Пользователь подключает mock mailbox и запускает сценарий; revoked connection виден; нет фиктивного success.

### TASK-012.10 — Аналитика и проверки

- [ ] Статус: planned.
- Зависимости: TASK-012.09.
- Реализация: Добавить connection/sync/action counters, безопасный audit, интеграционные тесты и E2E; обновить export/delete/retention.
- Критерии приёмки: Дедуп, privacy и удаление данных подтверждены; внешние проверки только с разрешением; release gate актуализирован.

## Ожидаемый результат

Работоспособные компоненты данного этапа, подключённые к существующему приложению; соответствующие миграции, API/UI/инфраструктура (где предусмотрено), автоматизированные тесты и подтверждённые результаты проверок.

## Правила выполнения и завершения

- Прочитать AGENTS.md и перечисленные документы, сверить зависимости и существующий код. При конфликте требований остановиться и зафиксировать вопрос, не менять согласованный контракт самостоятельно.
- Выполнять одну подзадачу за раз в порядке списка; все предыдущие подзадачи этого файла являются зависимостями, если явно не согласован иной порядок. Не переходить к следующей без указания владельца. Отмечать чекбокс только после выполнения критериев; при блокере указать partial/blocked.
- Для задач реализации писать настоящий код, миграции, конфигурации и тесты; подключать компоненты к приложению. Не заменять обязательную функциональность заглушками. Тестовые doubles допустимы только в тестах или явно обозначенном dev режиме.
- Проверять безопасность, owner scope, ошибки и ограничения там, где применимо. Не использовать реальные production secrets, не выполнять push/deploy без разрешения. Не добавлять функциональность других этапов заранее.
- Запускать применимые проверки из TESTING.md: unit/integration, race для конкурентного Go-кода, frontend lint/typecheck/build и E2E, migration/security checks. Записать фактическую команду, результат и непроверенные условия. Не утверждать, что тест прошёл, если он не запускался.
- Обновить затронутую документацию, список изменённых файлов, ADR при необходимости и статус ROADMAP. Весь этап завершён только после прохождения всех подзадач и итоговых критериев. Остановиться после отчёта.
