# TASK-003 — Файлы и изолированный обработчик

Статус: planned. Зависимости: 002.

## Цель

Создать приватное файловое хранилище и проверяемую границу изоляции.

## Источники требований

AGENTS.md; docs/ROADMAP.md; docs/REQUIREMENTS.md; docs/TESTING.md. Дополнительно (пути относительно docs/): modules/FILE_FLOW.md, SECURITY.md, DATABASE.md, API.md.

## Подзадачи и критерии приёмки

### TASK-003.01 — Файловая модель

- [ ] Статус: planned.
- Зависимости: зависимости этапа, указанные выше.
- Реализация: Написать миграции files и quota limits/reservations, состояния upload/ready/deleting, owner, hash, TTL; реализовать storage adapter S3. Добавить составные ключи, ready_at, owner-scope и инварианты DATABASE.
- Критерии приёмки: Доступ к чужой записи невозможен; object keys генерируются сервером; приватный bucket проверен. Приватный файл и ref несовместимого владельца отклоняются.

### TASK-003.02 — Загрузка

- [ ] Статус: planned.
- Зависимости: TASK-003.01.
- Реализация: Реализовать потоковый POST /files, ограничения размера даже без Content-Length, magic bytes, безопасное имя, hash, компенсацию незавершённой загрузки. Один файл на потоковый запрос. После инспекции и ready commit записать file.upload_completed в Outbox. Использовать временное хранение до проверки.
- Критерии приёмки: Нормальный файл загружается; превышение лимита/поддельный MIME/сбой S3 не оставляют доступный повреждённый объект. Проверить ровно 100 000 000 байт, превышение на байт и разрыв передачи без публикации.

### TASK-003.03 — Получение и удаление

- [ ] Статус: planned.
- Зависимости: TASK-003.02.
- Реализация: Реализовать GET /files и /files/{id}, cursor pagination, POST download с кратким TTL и DELETE с проверкой активной ссылки. Выдавать attachment URL ≤5 минут и не дольше TTL. Фиксировать download_link_issued.
- Критерии приёмки: Два пользователя не читают/удаляют чужие файлы; истёкшая ссылка не работает; pin препятствует удалению. Истёкший ресурс не выдаёт новую ссылку, выпуск ссылки не создаёт download_completed.

### TASK-003.04 — Квоты и очистка

- [ ] Статус: planned.
- Зависимости: TASK-003.03.
- Реализация: Написать атомарное резервирование байтов, учёт actual/reserved, TTL cleanup и reconciliation orphan objects; связать с удалением аккаунта. Проверить явный и TTL delete против pin, staging и удаление аккаунта.
- Критерии приёмки: Конкурентные загрузки не обходят квоту; активные ссылки сохраняются; повторная очистка идемпотентна. Cleanup и новый pin сериализованы, активная ссылка не теряет объект, orphan удаляется при повторе.

### TASK-003.05 — Изолированный launcher

- [ ] Статус: planned.
- Зависимости: TASK-003.04.
- Реализация: Реализовать согласованный в 000 sandbox launcher с фиксированными профилями, no network, non-root, read-only base, CPU/RAM/PIDs/disk/time limits, отдельным workspace и kill process group. Применить ADR-001 на целевом Linux, разделить профили изображений и PDF.
- Критерии приёмки: Тестовый процесс не читает секреты/host files и не выходит в сеть; таймаут останавливает потомков; нет Docker socket в API. При отсутствии ограничений launcher отклоняет запуск. После отмены/timeout и рестарта не остаются активные дочерние процессы или открытый workspace.

### TASK-003.06 — Проверки файлов

- [ ] Статус: planned.
- Зависимости: TASK-003.05.
- Реализация: Реализовать безопасное декодирование/инспекцию через sandbox с лимитами пикселей и страниц, отказ от повреждённых/зашифрованных PDF; cleanup временных файлов. Проверить безопасный профиль PDF и inclusive limits.
- Критерии приёмки: Fixtures проверяют malformed files, path traversal, oversized декодирование и cleanup; никакой обработки native parser в HTTP API. Повреждённые, интерактивные и зашифрованные PDF, превышение пикселей/страниц и ложный Content-Type отклоняются.

## Ожидаемый результат

Работоспособные компоненты данного этапа, подключённые к существующему приложению; соответствующие миграции, API/UI/инфраструктура (где предусмотрено), автоматизированные тесты и подтверждённые результаты проверок.

- Выполнять одну подзадачу за раз в порядке списка; все предыдущие подзадачи этого файла являются зависимостями, если явно не согласован иной порядок. Не переходить к следующей без указания владельца. Отмечать чекбокс только после выполнения критериев; при блокере указать partial/blocked.
- Для задач реализации писать настоящий код, миграции, конфигурации и тесты; подключать компоненты к приложению. Не заменять обязательную функциональность заглушками. Тестовые doubles допустимы только в тестах или явно обозначенном dev режиме.

- Обновить затронутую документацию, список изменённых файлов, ADR при необходимости и статус ROADMAP. Весь этап завершён только после прохождения всех подзадач и итоговых критериев. Остановиться после отчёта.
