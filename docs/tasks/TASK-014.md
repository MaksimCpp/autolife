# TASK-014 — AI Assistant

Статус: planned. Зависимости: 013.

## Цель

Реализовать AI-конструктор и ограниченные действия обработки информации.

## Источники требований

AGENTS.md; docs/ROADMAP.md; docs/REQUIREMENTS.md; docs/TESTING.md. Дополнительно (пути относительно docs/): modules/AI_ASSISTANT.md, modules/WORKFLOW_ENGINE.md, modules/AUTO_INBOX.md, modules/LIFE_PILOT.md, SECURITY.md.

## Подзадачи и критерии приёмки

### TASK-014.01 — Provider adapter

- [ ] Статус: planned.
- Зависимости: зависимости этапа, указанные выше.
- Реализация: Проверить актуальный API/модель и стоимость, написать adapter с timeout/rate limit, structured output, безопасной конфигурацией и mock.
- Критерии приёмки: Ошибки провайдера контролируемы; реальный API не вызывается в CI; secret не доступен UI/модели.

### TASK-014.02 — Бюджеты

- [ ] Статус: planned.
- Зависимости: TASK-014.01.
- Реализация: Реализовать usage reservations на запросы/токены/бюджет, reconcile actual usage и cost по версии тарифа, concurrency limit.
- Критерии приёмки: Параллельные запросы не обходят бюджет; ошибки освобождают reservation по политике; неопределённые расходы отмечены.

### TASK-014.03 — AI действия

- [ ] Статус: planned.
- Зависимости: TASK-014.02.
- Реализация: Написать ai.text.summarize/classify и ai.data.extract с allowlisted schemas, size limits, evidence/uncertainty, null для отсутствующих полей.
- Критерии приёмки: Malformed output отвергается; содержимое документа не даёт модели разрешений; стандартный FileFlow работает при недоступном AI.

### TASK-014.04 — Конструктор черновиков

- [ ] Статус: planned.
- Зависимости: TASK-014.03.
- Реализация: Реализовать /ai/workflow-drafts, передачу доступных schemas/actions/triggers, результат draft/clarification/unsupported, повторную системную validation.
- Критерии приёмки: Неизвестный action не регистрируется; недостающие параметры запрашиваются; валидный draft не активируется автоматически.

### TASK-014.05 — Подтверждение и UI

- [ ] Статус: planned.
- Зависимости: TASK-014.04.
- Реализация: Написать текстовый ввод, preview графа, список scopes/side effects, редактирование, ошибки/уточнения и явное подтверждение.
- Критерии приёмки: Без подтверждения запуск не создаётся; опасные внешние действия проверяются существующей политикой.

### TASK-014.06 — AutoInbox и LifePilot

- [ ] Статус: planned.
- Зависимости: TASK-014.05.
- Реализация: Подключить разрешённые AI extraction/digest к чекам, письмам и документам, сохраняя provenance, review кандидатов и настройки AI privacy.
- Критерии приёмки: Неизвестная гарантия не угадывается; prompt injection не изменяет workflow; отключение AI соблюдается.

### TASK-014.07 — Метрики и тесты

- [ ] Статус: planned.
- Зависимости: TASK-014.06.
- Реализация: Добавить ai request/usage/cost/draft acceptance events без prompts, тесты quotas/provider failure/injection/malformed output, human review.
- Критерии приёмки: Счётчики сверяются с usage; приватные входы отсутствуют в логах; E2E генерация→проверка→подтверждение проходит.

### TASK-014.08 — Объяснение ошибок AI

- [ ] Статус: planned.
- Зависимости: TASK-014.07.
- Реализация: Объяснять allowlisted ошибки и безопасные варианты исправления на RU/EN. Не передавать сырой текст, credentials и приватное содержимое.
- Критерии приёмки: Невалидный ответ или отказ провайдера даёт локализованную справку. Объяснение не запускает и не меняет workflow.

## Ожидаемый результат

Работоспособные компоненты данного этапа, подключённые к существующему приложению; соответствующие миграции, API/UI/инфраструктура (где предусмотрено), автоматизированные тесты и подтверждённые результаты проверок.

## Правила выполнения и завершения

- Прочитать AGENTS.md и перечисленные документы, сверить зависимости и существующий код. При конфликте требований остановиться и зафиксировать вопрос, не менять согласованный контракт самостоятельно.
- Выполнять одну подзадачу за раз в порядке списка; все предыдущие подзадачи этого файла являются зависимостями, если явно не согласован иной порядок. Не переходить к следующей без указания владельца. Отмечать чекбокс только после выполнения критериев; при блокере указать partial/blocked.
- Для задач реализации писать настоящий код, миграции, конфигурации и тесты; подключать компоненты к приложению. Не заменять обязательную функциональность заглушками. Тестовые doubles допустимы только в тестах или явно обозначенном dev режиме.

- Обновить затронутую документацию, список изменённых файлов, ADR при необходимости и статус ROADMAP. Весь этап завершён только после прохождения всех подзадач и итоговых критериев. Остановиться после отчёта.
