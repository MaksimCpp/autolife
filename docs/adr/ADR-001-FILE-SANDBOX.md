# ADR-001 — Изоляция файлового обработчика

Статус: принят в TASK-000. Верификация: TASK-003.05/06, TASK-007.01 и TASK-010.02.

## Решение

На Linux операторский launcher запускает одноразовый непривилегированный контейнер на задание с фиксированным allowlist профилей и проверяемых аргументов. Интерфейс worker → launcher принимает ID задания, профиль и ссылки на выделенное launcher рабочее пространство. Worker управляет загрузкой входов и сохранением проверенных выходов. Обработчик видит только выделенные входы и выходной каталог. Worker и API не получают произвольного управления runtime. Рабочие каталоги управляются launcher, пользовательские пути и произвольные host mounts запрещены.

Профиль включает read-only root, отдельное ограниченное рабочее пространство, выключенную сеть, drop capabilities, no-new-privileges, seccomp и AppArmor либо эквивалент, cgroup CPU/RAM/PIDs, дисковый лимит и timeout. В контейнер не передаются credentials, доступ к PostgreSQL, объектному хранилищу или runtime. Команды формируются из фиксированного списка аргументов. Launcher при отмене и timeout завершает группу процессов, подтверждает остановку, удаляет workspace. При рестарте отдельный cleanup сверяет рабочие пространства и запущенные задачи. При невозможности применить профиль запуск запрещён.

В MVP PDF допускается только по профилю SECURITY.md. Профили изображений и PDF раздельны. Нативные парсеры оставляют остаточный риск общего ядра. При недостаточной изоляции нужен отдельный узел или VM и отдельный ADR. Проверки выполняются на целевом Linux runtime. Локальный Docker Compose обеспечивает разработку и интеграционные тесты в поддерживаемом Linux окружении.

## Применение к расширенному FileFlow

TASK-007A сохраняет принятую границу и добавляет фиксированные профили документов, HTML и таблиц, расширяет профили растров и PDF. TASK-015 добавляет аудио/видео на той же границе. Отдельные digest, конфигурация ресурсов и fail-closed preflight обязательны; профиль назначает сервер. HTML требует также действующую браузерную песочницу. Проверки добавлены в TASK-007A и TASK-010.02.

## Граница проверок TASK-003 и TASK-010

TASK-003 реализует границу и проверяет fail-closed, парсеры и файловую бизнес-логику на доступном стенде. Полевая проверка профилей на Linux с AppArmor/cgroup v2 обязательна в TASK-010.02 и блокирует TASK-010.09. Сокет Docker остаётся только у оператора launcher; API обращается к выделенному Unix-сокету инспекции. Локальные тестовые адаптеры не входят в рабочие сборки.
