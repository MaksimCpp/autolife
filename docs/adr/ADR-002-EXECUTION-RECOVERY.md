# ADR-002 — Надёжное выполнение и восстановление

Статус: принят в TASK-000. Верификация: TASK-005 и TASK-010.05.

PostgreSQL — источник истины. Одна транзакция связывает execution, запись идемпотентности, quota reservation, pin всех входов, запись Transactional Outbox и River InsertTx. River job содержит execution ID. Transactional Outbox доставляет доменные события внутренним потребителям после commit. Повторная доставка безопасна: один durable checkpoint на потребителя и event ID, эффект и checkpoint в одной транзакции. River отвечает за доставку работы. CAS и монотонный fence защищают состояния execution и шагов независимо от redelivery.

Worker обрабатывает файлы вне транзакции, пишет в staging по уникальному ключу попытки и проверяет полноту выхода. Зафиксированный успешный шаг с приватными промежуточными ссылками можно использовать при возобновлении. Публичные для владельца ссылки полного результата, terminal state, release резервов и pin и событие фиксируются одной транзакцией. Fence устаревшего worker отклоняется. Удаление staging и orphan выполняется повторяемо. Полный контракт переходов задан в [Workflow Engine](../modules/WORKFLOW_ENGINE.md).

Reconciler сверяет зависшие исполнения, lease, staging, pin и резервирование. Перед освобождением ресурсов отменённого или просроченного запуска он проверяет остановку launcher. Сетевые операции будущих модулей сохраняют provider idempotency key либо используют сверку исхода. Неопределённый внешний эффект требует reconciliation и явного решения перед новым действием.

Backup состоит из зашифрованного согласованного набора PostgreSQL и объектов S3 с манифестом ключей и контрольных сумм. Минимальный журнал удаления хранится отдельно от восстанавливаемого снимка до окончания жизни всех затронутых копий. После commit privacy job и блокировки аккаунта запись об удалении синхронно подтверждается в отдельном журнале до HTTP 202 и до физической очистки. Обновление журнала идемпотентно по ID запроса. Сбой записи удерживает аккаунт в deleting, а reconciler повторяет запись. До её подтверждения HTTP 202 не выдаётся. При недоступном или неполном журнале восстановленная среда остаётся закрытой. При restore среда остаётся закрытой, пока не применены удаления, не сверены ссылки и квоты и не проверена готовность воркеров. Отсутствующий объект помечается недоступным. Полный drill подтверждает RPO/RTO, согласованность файлов и отсутствие удалённых аккаунтов и данных.
