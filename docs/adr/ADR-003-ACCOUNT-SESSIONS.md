# ADR-003 — Аккаунты, сессии и журнал удаления

Статус: реализовано в TASK-002.

Пароли хранятся как Argon2id с уникальной солью. Стартовые параметры 19 МиБ, два прохода и одна линия соответствуют рекомендации OWASP. На Apple M4 контрольный benchmark показал около 16 мс на хеш; один API-процесс выполняет максимум четыре вычисления параллельно. [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

Verify и reset используют одноразовый токен из 32 случайных байтов, в БД хранится SHA-256. Ссылка передаёт токен во фрагменте, интерфейс удаляет фрагмент при открытии. Mailpit используется как локальный адаптер. Повтор регистрации неподтверждённого аккаунта с тем же паролем позволяет запросить письмо повторно.

Сервер хранит SHA-256 непрозрачного токена сессии. Сессия действует семь суток, cookie использует HttpOnly и SameSite=Strict. HTTPS дополнительно использует Secure и префикс `__Host-`. Loopback HTTP предназначен для Compose. CSRF привязан к cookie и проверяется вместе с точным Origin. Pre-auth контекст подписан, действует 15 минут и отделён от сессии. Caddy перезаписывает заголовок IP клиента, API доверяет ему только в явно настроенной изолированной сети. PostgreSQL ограничивает попытки по HMAC источника и аккаунта в 15-минутном окне.

Экспорт текущих данных хранится в PostgreSQL как приватный JSON с TTL 24 часа. Ссылка действует до пяти минут и привязана к конкретной авторизованной сессии. Удаление в одной транзакции переводит аккаунт в deleting, отзывает все сессии и создаёт privacy job. API подтверждает запрос только после синхронизации записи отдельного журнала на диск. Worker может повторить эту запись по ID и применяет очистку по уже подтверждённому журналу.

В Compose API и worker используют общий отдельный том `restore-journal`. Его сохраняют отдельно от снимков PostgreSQL, минимум до выбытия всех затронутых резервных копий. В production журнал должен находиться на отдельном долговечном хранилище и быть видимым всем экземплярам API и worker. Применение журнала при restore проверяется в TASK-010 по [ADR-002](ADR-002-EXECUTION-RECOVERY.md).
