# Security — требования и threat model

## Активы и границы
Пароли, сессии, файлы, документы, сообщения, интеграционные credentials, workflow definitions и execution history. Границы: browser/API, DB/S3, queue/worker, sandbox, внешний provider. Угрозы: IDOR, account takeover, CSRF/XSS, SQL/command injection, SSRF, malformed files, resource abuse, secrets leakage, replay, prompt injection. Безопасность P0, не финальная косметическая задача.

## Identity/access
Argon2id с параметрами по benchmark и актуальной рекомендации; salt, rate limiting, generic auth errors. Opaque random session token, хранить hash, Secure/HttpOnly/SameSite cookie, rotation on login/password changes, TTL/revoke. CSRF protection для cookie mutations, Origin check; CORS allowlist, CSP и безопасные headers. Одноразовые hashed reset/verification tokens с TTL. Проверка owner/resource на каждом пути, включая S3 refs, jobs, results, nested IDs. Admin least privilege + audit; MFA до публичного admin UI. Secrets runtime injection, отдельные ключи, rotation, encrypted backups.

## File sandbox
Не root, read-only base, отдельное временное пространство, no network, drop capabilities, seccomp/AppArmor или эквивалент, cgroup CPU/RAM/PIDs, disk quota, timeout; no Docker socket/host mounts/DB secrets. Надёжная граница запуска sandbox: операторский отдельный launcher с фиксированными профилями либо иной согласованный изолятор; не давать API произвольный container control. Не доверять filenames, symlinks, content-type; check decoder limits/pixel/page counts, zip traversal/bombs. Только allowlisted args, без shell interpolation. Kill process group, очистить workspace, orphan reconciliation. Отклонять неподдерживаемые/зашифрованные файлы MVP. Presigned short-lived links, private bucket, TLS, limited permissions; скачивание с безопасными headers. Документировать остаточный риск native parsers.

## Future external/AI
SSRF protection для DNS, IP, redirect и browser subrequests; deny private ranges/metadata, egress restriction; no CAPTCHA bypass. OAuth state/PKCE/scopes, encrypted refresh tokens, revoke. Webhook signatures, replay prevention, dedup. AI input/output untrusted, validate schema; no direct secrets/authority, confirm risky effects. Нет пользовательского кода. Ограничить AI budget.

## Privacy/operations
Minimization, consent for optional telemetry, user export/deletion, retention and backup expiry, no contents/credentials in logs or analytics. Перед релизом определить юрисдикцию и проверить применимые законы, условия провайдеров, privacy/terms, incident process. Не заявлять формальное соответствие без проверки. Dependency scanning, secrets scan, SBOM по возможности, security updates, backups off-host and restore. Incident: disable affected capability, revoke tokens, contain, assess and notify where required. Release gate: adversarial tests, access matrix, sandbox verification, no known critical vulnerabilities; независимая человеческая проверка критических компонентов.

## Контракты P0

- Cookie с opaque token, Secure/HttpOnly/SameSite, TLS и узкий scope. Хеш токена хранится только на сервере. Login меняет идентификатор, password reset отзывает все сессии, изменение пароля отзывает остальные и ротирует текущую. Клиент может просмотреть и отозвать свои сессии. Нужна недавняя повторная проверка пароля для экспорта, удаления и его смены. Стартовое окно — 10 минут. Verify/reset одноразовые, стартовые TTL 24 часа и 30 минут соответственно. Ограничивать попытки по аккаунту и источнику, избегать раскрытия существования email.
- Same-origin мутации с cookie требуют Origin allowlist и CSRF header. Pre-auth формы получают короткоживущий токен отдельного контекста. Секреты и тела запросов не пишутся в журналы. Ссылку восстановления обрабатывать без сторонних ресурсов и с no-referrer.
- Использовать составные связи owner/resource и явную авторизацию каждого nested ID. Общая роль приложения не выдаёт privileged audit/export access. Изоляцию проверять матрицей двух владельцев, включая files, versions, execution steps, jobs и аналитику.
- Безопасный PDF-профиль MVP разрешает поддерживаемые статические документы. Отклонять шифрование, повреждённые или неоднозначные структуры, встроенные файлы, сценарии, формы, интерактивные и запускаемые действия. Ограничить глубину структуры, размер потоков и страницы. Проверять вход и нормализованный выход внутри sandbox. Выдавать результат как attachment с безопасным именем и заголовками, без inline preview. Ссылки с истёкшим ресурсом не перевыпускаются.
- Удаление аккаунта сначала блокирует новые операции и отзывает сессии. Затем отменяет или дожидается безопасной остановки активной работы, удаляет зависимости и закрытые копии данных по retention. Публикация restore разрешена после применения durable журнала удалений. Экспорт содержит доступные пользовательские данные MVP, имеет закрытый доступ и TTL 24 часа с готовности, исходный статус не раскрывается посторонним.
- Аудит фиксирует verify/reset, смену credentials, revoke, запрос и исход export/delete, отказы доступа и привилегированные изменения. Поля: время, тип, внутренний actor и ресурс либо минимальный псевдоним, outcome и request ID. Без credentials, содержимого и сырых email. Запись append-only для обычной роли, чтение под отдельной операторской ролью. Стартовый срок 90 дней с записи. Служебный журнал restore сохраняется как минимум до выбытия всех затронутых backup; сверх этого горизонта записи удаляются по согласованной политике.
