# AutoLife — функциональные и нефункциональные требования

P0 — MVP; P1 — следующий релиз соответствующего модуля; P2 — расширение; P3 — долгосрочное развитие. Данный документ — консолидированная версия продуктовых требований. Спецификации модулей детализируют их, не изменяя согласованный объём. Конфликты согласовываются до реализации.

## Бизнес-правила
Каждый приватный ресурс имеет владельца. Сервер проверяет разрешения на каждом обращении. Архив запрещает новые запуски; деактивация останавливает автоматические триггеры, но не текущие задачи. Версия execution неизменна. Закрытие вкладки не отменяет фоновое выполнение. Ошибка обязательного шага останавливает зависимые действия. Результаты не заменяют исходники. Истёкшие файлы обозначаются недоступными. Внешние необратимые действия не повторяются вслепую; пользователь подтверждает чувствительные операции. Необязательная аналитика зависит от согласия.

Проверить на нагрузочном стенде, задокументировать конфигурацию и уточнить лимиты до публичного релиза. Все квоты проверяются атомарно на сервере. API и воркеры масштабируются независимо. Стартовые параметры не являются подтверждёнными показателями. Данные времени в UTC, календарные даты и timezone отдельно; деньги decimal/minor units с валютой.

## Безопасность и UX
HTTPS; хеширование паролей, безопасные сессии, CSRF/XSS/SSRF-защита, изоляция файловых обработчиков, ограничение CPU/RAM/диска/времени, секреты вне логов и репозитория. Без произвольного кода. Поддержка RU/EN, тёмная и светлая темы, синий/голубой/бирюзовый/изумрудный акценты, адаптивность, клавиатура, контрастность, состояния ошибок/загрузки. Подробнее SECURITY.md, UI_UX.md.

## Приёмка MVP
Сквозной тест: пользователь регистрируется, загружает файлы, строит последовательность, запускает, закрывает страницу, возвращается и скачивает результат; повторяет сценарий. Некорректная конфигурация, чужие ресурсы, опасные файлы, превышение квот, сбой воркера и отмена проверяются отдельно. Аналитические события не дублируются; секреты и содержимое файлов не попадают в аналитику. Проверены миграции, тесты, мониторинг, backup/restore, HTTPS. Нет известных блокирующих дефектов. Невыполненные P0 требуют решения владельца.

## Правила ресурсов и хранения

МБ = 1 000 000 байт, Мпикс = 1 000 000 декодированных пикселей. Счётчики целочисленные, лимит включителен. При превышении прекращать приём или обработку до публикации, возвращать понятную ошибку, освобождать резерв после подтверждённой остановки. Для 50 файлов считаются входные ссылки, для 500 страниц — суммарные страницы PDF-входов и отдельно PDF-выходов. На каждом шаге проверяются лимиты декодирования и итоговых артефактов. В активные 2 запуска входят queued/running/retrying/cancel_requested. Queue start deadline считается от принятия, runtime deadline от первого захвата и включает повторные попытки и backoff. Сравнение дедлайнов использует UTC и правило now ≥ deadline.

Отдельно конфигурируются глобальная и пользовательская очереди, параллельные загрузки, суммарное хранилище, временный диск и промежуточные артефакты, CPU/RAM/PIDs и время отдельного профиля. Без валидных значений профиля worker не принимает файловые задания. TASK-003 и TASK-010 измеряют память, диск, egress и fairness. При насыщении возвращаются управляемые quota/rate/unavailable ошибки.

Сроки считаются от ready_at для файлов, terminal_at для истории, записи для логов, завершения снимка для backup. 7/30/14/7 дней означают интервалы по 24 часа. Активный pin защищает объект от физического удаления, истечение блокирует выдачу новых URL и новые pin. Сроки аналитики и служебных данных определены в ANALYTICS и SECURITY. Стартовые цели конфигурируемы и проверяются нагрузкой. 99,5% измеряется по внешним проверкам за календарный месяц, полный FileFlow probe наблюдается отдельно. p95 API измеряется по группам JSON-операций, принятия — до durable commit, время ожидания и обработки отдельно. RPO/RTO проверяются полным restore PostgreSQL+S3.

## Дополнения к функциональным требованиям

FILE-01 использует потоковую серверную загрузку отдельных файлов с контролируемой параллельностью и порядком ссылок. FILE-02 включает JPEG/PNG/WebP/PDF. HEIC и ZIP выделены в FILE-03. WF-02 проверяет снимок черновика без изменения active_version. WF-03 включает file_uploaded и ограниченные условные переходы P1, параллельный DAG P2. AI-01 включает безопасное объяснение ошибок. USER-02 проверяется после интеграции всех P0 доменов. ADMIN-01 охватывает P0 журнал действий аккаунта и доступа. BILL-01 включает Team после workspace и модели плательщика. Для UI обязательны WCAG 2.2 AA, RU/EN, светлая и тёмная темы, мобильные сценарии. Этапы проверок приведены в [TESTING](TESTING.md).
