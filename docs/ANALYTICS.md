# Аналитика AutoLife

## Источники и границы

Пользовательская статистика строится по собственным execution, usage и закрытым агрегатам. Технические метрики берутся из API, PostgreSQL/River, worker, S3 и внешних probes. Агрегаты владельца платформы используют обязательный операционный учёт в минимальном объёме и необязательную телеметрию с отдельным согласием и измеримым охватом. Полная продуктовая панель, MRR и churn появятся в TASK-015. P0 сбор начинается при реализации доменов в TASK-002–007A, обработчики и панели устанавливаются к TASK-009.

Обязательный поток служит исполнению, квотам, доступности, безопасности и истории. Необязательный поток служит продуктовому UX и воронкам. Их цели, ACL, поля и retention отличаются. Opt-in по умолчанию выключен. Настройка доступна в профиле, применяется до необязательной записи, при отзыве прекращает сбор и запускает удаление связанных raw событий и пересчёт затронутых агрегатов. Минимальные полностью обезличенные агрегаты сохраняются по утверждённой политике с подавлением малых групп. Порог для P0 — 10 уникальных участников. Псевдонимизация идентификатора не равна обезличиванию.

## Версионируемый словарь

Канонические имена используют формат domain.event. Envelope версии 1 содержит event_id UUID, event_type, schema_version, occurred_at UTC, purpose и минимальные свойства из allowlist. Для оперативных записей допустимы owner_id и ID ресурсов по назначению. Для optional stream используется отдельный псевдоним участника. В product properties запрещены имена файлов, письма, URL/query, документы, токены, prompts, email, определения сценариев, суммы и любые свободные строки. Prometheus labels используют только ограниченные значения. Изменение схемы требует новой версии и поддержки совместимых consumers до завершения миграции.

Producer пишет событие в Transactional Outbox вместе с доменным commit. Потребитель фиксирует эффект и отметку обработки в одной транзакции. Дополнительный логический ключ защищает от повторного создания события. Поздние записи учитываются при пересчёте UTC-дня, повтор доставки не прибавляет значение повторно. Отказ аналитики не прерывает основную работу. Начальный срок outbox — 7 дней после обработки всеми обязательными потребителями. Необработанные события сохраняются и поднимают тревогу по age/depth. Опциональные raw хранятся 90 суток с occurred_at, обезличенные агрегаты — 12 календарных месяцев с окончания периода. Операционная история — 30 суток с терминального состояния, технические логи — 14 суток с записи. Аудит следует SECURITY.md.

## Метрики

| Метрика | Источник и вычисление |
|---|---|
| DAU/WAU/MAU | Уникальные авторизованные с workflow.created или принятым execution, UTC-окна 1/7/30 календарных дней. |
| Activation | Доля новых аккаунтов с первым succeeded в течение 7 суток с регистрации, полностью наблюдаемые когорты. |
| D7 retention | Доля регистрационной когорты с полезным действием на седьмой UTC-день. |
| Success rate | succeeded / (succeeded + failed + timed_out) по terminal state в окне. Cancelled отдельно, нулевой знаменатель отображается как отсутствие данных. |
| Time to value | Медиана и p95 first_success_at − registered_at среди активированных. Рядом показывается activation. |
| Повторное использование | Доля активированных с повторным success в другой UTC-день в течение 14 суток, см. PRODUCT. |
| Usage | Logical executions, логические файлы, байты успешных шагов и ресурсы всех попыток показываются раздельно. Сумма по шагам отражает повторную обработку одного входа при разных действиях. |
| Saved time | max(0, baseline − active user minutes), с опубликованным методом и без подмены времени пользователя wall time воркера. |
| MRR, churn | Нормализованная месячная стоимость активных подписок по валютам. Churn — ушедшие платящие / платящие на начало периода. |
| Технические SLI | p95 JSON API и durable acceptance, queue age/depth, ошибки, CPU/RAM/disk, DB pool, стоимость и внешняя доступность. |

PostgreSQL агрегирует с воспроизводимым ключом по UTC-дню, scope, metric и dimensions. Использовать Recharts для кабинета, Prometheus/Grafana для техники. PostHog/ClickHouse требуют доказанной нагрузки или потребности и отдельного ADR. Тесты покрывают consent, удаление и пересчёт, late events, дедупликацию, два owner, восстановление и сверку с первичными источниками.

## Конвертации FileFlow

В TASK-007A добавить совместимую версию `file.action_completed` с ключом step_id, версией action, enum входных/выходных форматов, числом входов и выходов, байтами, временем обработки, outcome и safe reason enum. Для смешанного пакета вести числовые счётчики по формату без приватных свойств. TASK-009 строит гистограммы популярности, число логических конвертаций (один terminal step), отдельно число файлов, объём входа/выхода, среднее время обработки без очереди, p95, доли успеха/ошибки и причины. Знаменатель — succeeded + failed + timed_out, отмены отдельно. Повторная доставка и retry не дублируют логический исход.

Технический учёт включает CPU-секунды, пик RAM и по возможности RAM-время, пик и время временного диска, очередь, S3-операции, байт-дни и измеренный трафик; ресурсы всех попыток учитываются по attempt ID отдельно от продуктовых конверсий. При недоступной метрике фиксировать отсутствие измерения. Измеренный S3-трафик не равен завершённым клиентским скачиваниям. Лимиты, ACL, согласие для необязательных UX-событий и удаление следуют общей политике. Запрещены содержимое, имена, хеши, URL, извлечённый текст и свободный вывод инструментов.

В TASK-005 потребитель execution-событий использует `outbox_consumptions` и атомарные агрегаты по типу и безопасному outcome. Worker публикует счётчики, накопленную длительность, глубину очереди и активные задачи на внутреннем `/metrics`. Содержимое входов, выходов, имена файлов и ID владельца не используются как labels.

В TASK-006 счётчики попытки содержат безопасный агрегат форматов, число файлов и байты. Успех или терминальный отказ фиксирует одно `file.action_completed` на логический шаг. Повторы сохраняются отдельно. Внутренние метрики агрегируют длительность, байты входов и выходов и количество результатов без пользовательских идентификаторов.

`file.action_attempted` версии 1 записывается для каждой завершённой попытки с отдельным ключом execution/step/attempt. Логический `file.action_completed` версии 1 остаётся отдельным событием. Технические ряды содержат время попыток и байты учтённых входов/выходов. При наличии выборки Docker stats суммируется наблюдённый CPU и берётся максимум наблюдённой RAM, с отдельным счётчиком выборок. Для короткой или прерванной задачи измерение может отсутствовать. Это выборочные измерения, а не максимальные показатели cgroup за всё время. Успешные серверные операции GET/PUT S3 и прочитанные или записанные байты учитываются отдельно по попыткам. Пик и время временного диска, байт-дни и физический сетевой учёт, включая повторы транспортного уровня и скачивания, остаются открытыми. TASK-009.04/.05/.07 завершает обработку и агрегацию, включая байт-дни. TASK-010.04/.06 измеряет tmpfs и физический трафик и сверяет учёт на целевой инфраструктуре.
